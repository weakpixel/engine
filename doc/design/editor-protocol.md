# Editor protocol

The JSON messages between the level editor (`editor/bridge`) and a host.
The design of the editor around it is in [editor.md](editor.md); the tool shell's messages are in [tool-shell.md](tool-shell.md).

## Protocol

JSON objects with a `"type"`, version 0 (`bridge.Version`, sent in `ready`; it stays 0, with no compatibility code, until the first release).
Components are named by their key `group:name` ([identity](../guide/ecs/game-object-definition.md#identity)) everywhere: in documents, `edit.component`, the first element of a `field` path and error texts.
The bridge queues incoming messages and handles them at the start of the next tick, on the game goroutine, because a JavaScript callback can run while the game goroutine is blocked mid-frame.

| Direction | Type | Fields | Meaning |
| --- | --- | --- | --- |
| game → host | `ready` | `version`, `schemas`, `components`, `assetKinds` | First tick. `schemas` is every registered object schema (`{group, class, doc?, goType?, components}`, the GOD's object entry); each component is `{component: "group:name", field, optional?, readonly?, schema, doc?, embeddedVia?}` (the GOD's object component entry with its `schema`). `components` is every registered component type, `{group, name, doc?, goType?, schema}` sorted by key: an object may hold any of them ([extra components](../guide/ecs/game-object-definition.md#extra-components)), so the inspector offers them. `assetKinds` maps file suffixes to asset kinds. |
| game → host | `applied` | `error` | Answer to each `document` and `open`; `error` is `""` when it was applied. A document waiting for prefabs is answered once they loaded; a saved prefab that re-applied the document sends one unasked. |
| game → host | `objects` | `objects: [{id, group, class, prefab?, part?}]` | The level's objects after an open or apply; `prefab` is an instance's prefab key, `part` the id within the prefab of an object of a multi-object instance that is not its root (its `id` is `<root id>/<part>`; parts follow their root). |
| game → host | `selection` | `ids` | The selection changed in the viewport (or objects disappeared). |
| game → host | `edit` | `id`, `component`, `json`, `override?`, `part?` | A drag ended: replace the value of that component (its key, `gfx:Transform`). With `override` (a prefab instance) `json` is the component's override; `{}` drops it. With `part`, `id` is the instance root and `json` the override of that part, for `children.<part>` of the entry. |
| game → host | `mode` | `play`, `paused?` | Play or Stop happened, or a `pause` paused or resumed Play (`paused` is set while Play is paused). |
| game → host | `entities` | `entities: [{entity, id?, components, errors?}]`, `truncated`, `missing?` | Answer to `inspect`: the live values. `entity` is `"<index>.<generation>"`, `id` the document id (none for an entity a system spawned), `components` every component the types registry knows that the entity has, encoded as the document holds them (asset keys, ids; a reference to an entity that is no level object is written `"#<index>.<generation>"`), `errors` those that failed to encode. Components registered only with `ecs` are not listed: the ecs API cannot name them. `truncated` says the limit cut the list; `missing` lists asked ids with no live object. |
| game → host | `status` | `tick`, `play`, `paused`, `scenes`, `tps`, `draws` | Answer to `status`: the bridge's tick count (the tick that handled the request included), the mode, the names of the engine's scene stack, bottom first, the tick rate of the current [pacing](../guide/engine/editor.md#pacing) state (not the active rate a wake runs the answering tick at) and the frames drawn so far. |
| game → host | `create` | `object` | Append this object (fresh id) to the document. |
| game → host | `choose` | `path`, `x`, `y`, `options` | A drop fits several object types; ask the user, then resend the `drop` with `class`. |
| game → host | `camera` | `x`, `y`, `zoom` | The editor camera stopped moving (about 250 ms after a pan, zoom or frame). |
| game → host | `mapLayers` | `layers: [{map, name, path, kind, layer, hidden}]` | The tile and image layers of the Tiled map behind the level, in draw order (`map` the `.tmj` key, `path` the Tiled layer path, `kind` `tiles` or `image`, `layer` the render layer the game spawned it on, `hidden`). Built from the world's `tilemap.TileLayer` entities and sent when the list changes, not every tick: after an open, once the backdrop is ready, after a map hot reload or a `mapLayerHidden`. An older host ignores it. Object and group layers spawn nothing and are not listed. |
| game → host | `screenshot` | `id`, `png` (base64), `width`, `height`, `tick`, `error?` | A capture: the answer to a host `screenshot` (its `id` echoed), or a capture the game took itself (hotkey, environment variables) with `id` `""`. Under the bridge the game never writes a file: the bridge installs the screenshot sink and the host decides where the PNG goes. On failure `png` is empty and `error` says why (bad target, scale outside 1..8, image over the size limit). Same shape as the tool protocol's, built by `editor/shotproto`. |
| game → host | `error` | `message` | A message could not be handled, or an asset failed to load or reload (a `.kage` that no longer compiles): the host wraps `Config.OnAssetError` with `Bridge.ReportError`. The game's own `OnAssetError` still runs. |
| host → game | `document` | `text` | The level document's current text. |
| host → game | `open` | `path`, `text` | Switch to another file: `text` is its document, `path` its asset key (the level's asset scope and `game.Level.Path`). Play stops, the selection is cleared and the level is framed unless a `camera` follows. Answered like `document`; later `document`s apply to this file. |
| host → game | `assetsChanged` | `paths` | Files under the asset root changed (relative paths): `asset.Server.Changed`. |
| host → game | `select` | `ids`, `reveal?` | Select these objects (from the outline). With `reveal` the camera pans to them when they are not in view (`Session.Reveal`): the union of their bounds must lie inside the visible world rectangle shrunk by 10% per side, else the camera centers on it; zoom is unchanged. Without it the camera never moves. The pan is reported as `camera`. |
| host → game | `mapLayerHidden` | `map`, `path`, `hidden` | Hide or show a map layer in edit mode (`Session.SetMapLayerHidden`): sets `TileLayer.Hidden` of that layer's entity and writes nothing to the map (Tiled owns the file). Play and Stop keep it; a new backdrop or a map hot reload starts from Tiled's visibility again. `mapLayers` reports the result; an unknown layer answers `error`. |
| host → game | `screenshot` | `id`, `target?`, `scale?`, `keepAlpha?` | Take a capture of the next drawn frame (`Engine.Screenshot`): `target` `"game"` (default, the logical frame, post passes included) or `"window"` (final pass and letterbox), `scale` 1..8 for `game`. Answered by `screenshot`; an unknown `target` is answered at once with `error` set. Neither target contains the editor's selection, markers or outlines. |
| host → game | `drop` | `path`, `x`, `y`, `class?` | A file was dropped on the canvas at device pixels `x, y`. A `*.prefab.json` makes an instance of it. |
| host → game | `play`, `stop`, `step`, `frame` | none | Mode commands; `frame` centers the camera. `step` runs one tick in edit mode or in a paused Play. |
| host → game | `pause` | `paused` | Pause (`true`) or resume Play (`Session.Pause`): a paused Play is `TickPause` without a reset, so the game keeps drawing and `step` advances it. Answered with `mode` when it changed; ignored in edit mode. |
| host → game | `inspect` | `ids?`, `components?`, `all?`, `limit?` | Read live values: the level's objects (`ids`, else all in document order), and with `all` every other entity in index order, at most `limit` (default 100), only the component keys in `components` when given. Answered by `entities`. Works in both modes. |
| host → game | `status` | none | Answered by `status`. |
| host → game | `input` | `keys?`, `mouse?`, `pad?`, `ticks?` | Hold input in Play for `ticks` game ticks (default 1) on top of the devices (`Session.Inject`): `keys` by `input.Key` name, `mouse` `{x, y, buttons, wheelX, wheelY}` (logical pixels; buttons `left`, `middle`, `right`, `back`, `forward`), `pad` `{buttons, axes, triggers}` (buttons by their bindings name after `pad:`, axes left x, left y, right x, right y). The pad is a virtual gamepad (`editor.InjectedPad`) announced as connected the first time. A new `input` replaces what is left of the last; edit mode ignores it, Stop drops it, and a paused Play holds it until ticks run. Unknown names answer one `error` and nothing is held. |
| host → game | `camera` | `x`, `y`, `zoom` | Restore the editor camera (after a rebuild, before the document); the level is then not framed on open. Not reported back. |
| host → game | `settings` | `snap?`, `colliders?`, `animate?`, `background?`, `stage?`, `rate?` | `animate` (default true) lets the level move on its own in edit mode and in a prefab stage; false freezes its sprite clips, animated tiles, particles and shader time there ([pacing](../guide/engine/editor.md#pacing)), and Play always animates. `rate` is `{idle?, active?, hidden?}`, the [pacing](../guide/engine/editor.md#pacing) rates in ticks per second (defaults 10, 60, 0; `.weakpixel.json` `editor.rate`); bad rates answer `error` and change nothing. The drag snap grid in world units, 0 for off, `colliders` shows (default) or hides the collider outlines of edit mode, `background` the level stage's background in edit mode (`#rrggbb`, `""` for the game's own `Config.Background`; Play shows the game's own, Stop the host's again; a prefab stage ignores it), and in a prefab stage its look: `stage` is `{background?, grid?}` (`#rrggbb`, grid step in world units). Only the parts present change; the extension takes them from `.weakpixel.json` (`editor.snap`, `editor.prefab`), and a host may follow its light or dark appearance with `background`. In a web page the editor build's screen is transparent (`editor/host`), so the bars around the letterboxed screen show the page's own background. |
| host → game | `visible` | `visible` | The host shows (`true`) or hides the view: hidden, the game ticks at the hidden rate (0: not at all, until the next message) and draws nothing; shown again counts as activity. A host that never sends it is always visible. Without `visible` the message answers `error`. |
| host → game | `create` | `class` or `prefab` | Make a new object of `group:class`, or an instance of the prefab key, at the view center; answered with `create`. |
| host → game | `assetField` | `id`, `field`, `path` | A file was dropped on an inspector asset field (`field`: component, then properties); answered with `field` or `error`. |
| game → host | `field` | `id`, `field`, `value` | Write `value` (an asset key) at `field` of object `id`. |

**Drops.**
The file's suffix gives its asset kind (`AssetKinds`).
Candidates are object types with a required component that has an asset field of that kind.
Exactly one candidate creates an object; several ask the host to choose; none is an error.
The new object has every required component at its initial value (the schema's `default`s from `+game:default`, else zero), a `gfx:Transform` at the drop point, and the file's key in the asset field (the component's `ID` if it is of that kind, else the first by name; an `*.anim.json` gives its default clip).
A `*.prefab.json` (asset kind `prefab`) is not a field value: it becomes `{"id": "<prefab name>-<n>", "prefab", "components": {"gfx:Transform": <position override>}}`.
Go code names the key `editor.TransformKey`.
**Default layer.**
When the level has a Tiled backdrop whose map has an object layer, a new object lands between the map's tile layers as it would in Tiled: every drawn component it has (`gfx:Sprite`, `gfx:NineSlice`, `gfx:Label`, `gfx:Particles`) gets `Layer` set to the render layer of the nearest tile or image layer below the map's topmost object layer (so `BaseLayer` and the game's `LayerFor` are respected), or the map's lowest render layer when none is below.
With several maps (a world) the map containing the drop point is used, else the first.
A prefab instance gets it too, as an override written only when it differs from the prefab's own `Layer`.
Without a backdrop map or an object layer nothing changes (`Session.DefaultLayer` reports which).
